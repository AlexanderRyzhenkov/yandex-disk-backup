# Yandex Disk Backup

Bash-скрипт для загрузки локальной копии Яндекс Диска на флешку, внешний диск или в каталог Linux. Скрипт использует официальный консольный клиент `yandex-disk` и всегда запускает синхронизацию с `--read-only`: локальные изменения не загружаются в облако.

Это локальная синхронизируемая копия, а не архив с историей версий. Скрипт не создаёт снимки, не задаёт срок хранения и не гарантирует восстановление ранее удалённых или изменённых файлов. Для хранения истории отдельно архивируйте копию или используйте снимки файловой системы.

## Требования

- Linux, Bash и GNU coreutils (`realpath`).
- Установленный [консольный клиент Яндекс Диска](https://yandex.ru/support/yandex-360/customers/disk/desktop/linux/ru/).
- Доступ к интернету и достаточно свободного места на носителе.

## Быстрый запуск

Поместите проект на нужный носитель и откройте его каталог. Выполните первичную авторизацию:

```bash
bash backup.sh --init
```

Следуйте инструкциям клиента. Он сохраняет данные авторизации в `.yadisk_conf/passwd`; скрипт создаёт рядом `config.cfg`. Затем загрузите файлы:

```bash
bash backup.sh
```

По умолчанию копия находится в каталоге `yandex-disk` рядом со скриптом. Запуск через `bash` работает и на носителях без разрешения исполнять файлы. Ошибка клиента завершает скрипт с ненулевым кодом, без сообщения об успешном завершении.

## Настройки

Передайте настройки через переменные окружения. Относительные пути отсчитываются от каталога скрипта, независимо от текущего рабочего каталога терминала.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `YADISK_CONF_DIR` | `.yadisk_conf` | Каталог с данными авторизации и конфигом клиента. |
| `YADISK_LOCAL_DIR` | `yandex-disk` | Каталог локальной копии. |
| `YADISK_EXCLUDE_DIRS` | Не задана | Исключаемые каталоги в облаке через запятую, без пробелов вокруг разделителя. |

Пример отдельных каталогов и исключений:

```bash
export YADISK_CONF_DIR="$HOME/.config/yadisk-backup"
export YADISK_LOCAL_DIR="/media/usb/yandex-copy"
export YADISK_EXCLUDE_DIRS="Downloads,Temporary"
bash backup.sh --init
bash backup.sh
```

Сохраните эти команды `export` в личном файле вне репозитория или задавайте их перед каждым запуском. При повторном запуске используйте тот же каталог авторизации. Не добавляйте токены в переменные, команды или исходный код: авторизацией занимается клиент.

Когда `YADISK_EXCLUDE_DIRS` не задана, действуют исключения из `config.cfg`. Конфиг клиента использует формат `name=value`, например `exclude-dirs="Downloads,Temporary"`. Пути к копии и авторизации скрипт передаёт через аргументы команды, поэтому перемещение всего проекта не требует перезаписи этих путей в конфиге.

## Работа с существующей копией

Для перехода с прежнего скрипта укажите существующие каталоги в `YADISK_CONF_DIR` и `YADISK_LOCAL_DIR`. Повторная авторизация не нужна. Если старый `config.cfg` использует строки вида `dir: ...` или `exclude-dirs:`, исправьте формат на `name=value`; строку `dir` можно убрать, поскольку скрипт передаёт путь сам.

## Безопасность и ограничения

- Не публикуйте `.yadisk_conf`, `passwd`, `config.cfg`, журналы и содержимое локальной копии. Конфиг тоже может содержать секреты, например пароль прокси.
- `.gitignore` разрешает добавлять только `backup.sh`, `README.md` и сам `.gitignore` в корне проекта. Новые файлы проекта добавляйте в этот список осознанно. `git add -f` обходит защиту; перед коммитом проверяйте `git diff --cached`.
- Скрипт задаёт `umask 077` для новых файлов. FAT/exFAT и некоторые настройки монтирования не поддерживают индивидуальные права Unix; защищайте носитель отдельно. Уже существующие права скрипт не меняет.
- Каталоги авторизации и копии не могут совпадать или находиться друг внутри друга. Не используйте для копии каталог с посторонними ценными файлами.
- `--init` не перезаписывает существующие данные авторизации или конфиг. Для другого аккаунта используйте отдельные каталоги.
- Запускайте только одну синхронизацию для выбранного каталога. Не используйте его одновременно с фоновым клиентом Яндекс Диска. Скрипт не управляет уже работающим демоном.
- Скрипт не включает `--overwrite`. При конфликтах клиент может переименовывать локально изменённые файлы. Подробности описаны в [справке по командам клиента](https://yandex.ru/support/yandex-360/customers/disk/desktop/linux/ru/cli-commands.html).
- Перед запуском убедитесь, что внешний носитель смонтирован в ожидаемом месте. Скрипт создаёт отсутствующий каталог и не проверяет точку монтирования.

## Проверка синтаксиса

```bash
bash -n backup.sh
bash backup.sh --help
```

Эти команды не запускают авторизацию или синхронизацию. Для проверки полного сценария используйте отдельные каталоги и тестовые данные.
